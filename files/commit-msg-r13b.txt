Round 13 follow-up: paint text boxes instead of a single line

Report: "The text box tool is not properly working. It's just a single line
instead of a box".

The node was never the problem. The rect, the wrapped content, the font size
and the alignment all reached the document, and text_box_model.dart's wrap and
line-origin maths was already unit-tested. The defect was one missing branch:
_drawShape in tiled_canvas_painter.dart had no 'TEXT' case, so every text box
fell through to the polyline default and its two bbox corner pts were drawn as
ONE diagonal stroke. That is exactly what a text box looked like - a line.

Added text_box_painter.dart (layout, clip, glyph painting, colour/size wiring)
and the missing dispatch case. Conventions mirror pc_agent/viewport/
text_renderer.py so the tablet and the PC mirror agree: bbox inset by
kTextPadding, the same greedy word wrap, clipped to the box, and no outline of
its own.

Two more surfaces had the same hole:

- thumbnail_renderer.dart drew the same diagonal for a TEXT node. A thumbnail
  cannot render glyphs at that scale, so it now draws a translucent block
  instead of a misleading line (the TABLE case already did this).
- paintNodeFill would have laid an opaque rect over the glyphs; TEXT now skips
  the generic rect while still honouring a fill as a background.

Tests assert on what the painter EMITS, not on the model. A model-level test
would have passed through the entire bug. They also assert the dispatch itself
at source level, because a missing branch is invisible to a unit test that
exercises the branch's own function - mutation-checked by deleting the case and
confirming the tests fail.

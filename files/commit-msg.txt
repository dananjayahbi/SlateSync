Round 12 (part 6): polygon and text box models, plus PC text rendering

Issue 05. Two design decisions were forced by the existing schema and are
worth recording, because the obvious alternatives do not work:

* POLYGON reuses SHAPE + shape_type PATH with its vertices in geometry.pts.
  No schema change, and both painters already render PATH -- a separate
  POLYGON shape type would have meant touching every renderer to draw
  something they can already draw.
* TEXT travels in graph_config ({"text", "font_size", "align"}), exactly as
  TABLE stores its grid. NodeStyle is frozen and geometry.pts is numeric
  only, so there is nowhere else for a string to live without unfreezing the
  node model.

Text needed attention beyond the obvious path: once TEXT became a reachable
shape_type, the PDF exporter and the thumbnail renderer would have drawn a
frame around the box (they outline every shape). Both now delegate TEXT, so
the box looks the same everywhere rather than being framed in three of four
renderers.

Polygon hit-testing is boundary-inclusive on purpose: tapping exactly on an
edge should select the polygon, not miss it.

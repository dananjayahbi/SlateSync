Round 12 (part 7): wire the polygon, text and OCR tools into the canvas

Polygon commits SHAPE+PATH with the vertices from regularPolygonInBox; the text
tool commits SHAPE+TEXT and immediately opens the keyboard editor, then writes
the result back into graph_config; the OCR tool draws a free-hand outline and
its panel drives the PC job, inserting the returned text as a real text box.

Three genuine bugs surfaced while wiring this, all of the kind that would have
shipped as "the feature does not work" and none visible from the code alone:

1. The OCR overlay was a CONDITIONAL Stack child. Adding it changed the number
   of unkeyed children above the ToolDock, so Flutter remounted the dock —
   which destroyed an open property panel mid-interaction. The slot is now
   always present and merely paints nothing for other tools.
2. CustomPaint hit-tests like any other box, so the overlay swallowed the very
   drag it existed to visualise. It is now unconditionally pointer-transparent.
3. The OCR panel lives in the dock's OverlayEntry, which is NOT in this page's
   element tree, so setState never reached it: the outline, progress and errors
   would all silently never appear. It now listens to its own notifier.
   Separately, the running flag was cleared only AFTER `await sub.cancel()`,
   leaving the panel stuck on "scanning" for a frame after the job ended.

Also hardened two lifetime edges: the notifier is guarded against use after
dispose (an OCR job can outlive the page), and `_bumpOcr` is safe to call from
any async continuation.

23 integration tests; flutter analyze clean; full mobile suite 659 green.
